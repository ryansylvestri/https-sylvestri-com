# n8n Lead Intake Router

This runbook defines the production lead router for `sylvestri.com`.

## Architecture

- Browser forms post only to `POST /api/lead` on `sylvestri.com`
- The app forwards normalized lead payloads to n8n using `LEAD_ROUTER_URL`
- The app signs the payload with `LEAD_ROUTER_SIGNING_SECRET`
- n8n is the primary router into Follow Up Boss and any downstream automation
- The app keeps direct Follow Up Boss fallback when the router is unavailable
- The app owns SMTP notifications to `bot@sylvestri.com`

## Required headers from the site

- `Content-Type: application/json`
- `X-Lead-Request-Id: <uuid generated by app/api/lead>`
- `X-Lead-Signature: <sha256 hmac of raw request body using LEAD_ROUTER_SIGNING_SECRET>`
- `Authorization: Bearer <LEAD_ROUTER_TOKEN>` when `LEAD_ROUTER_TOKEN` is configured

## Recommended workflow graph

1. `Lead Intake Webhook`
   - `POST`
   - dedicated path, for example `/lead-intake-router`
   - respond with JSON
2. `Auth Header Validation`
   - reject when bearer token is missing or does not match the configured secret
3. `Signature Validation`
   - recompute `sha256` HMAC over the raw body using `LEAD_ROUTER_SIGNING_SECRET`
   - reject on mismatch
4. `Payload Validation`
   - require `requestId`, `fullName`, `email`, `leadType`, `source`, `campaign`, `sourcePath`, `submittedAt`
   - require `propertyAddress` for `home-valuation` and `seller-distress`
5. `RequestId Dedupe Lookup`
   - use a persistent n8n Data Store or Redis-backed lookup keyed by `requestId`
   - reject duplicates deterministically with a `200` idempotent response
6. `Create Follow Up Boss Event`
   - use `POST https://api.followupboss.com/v1/events`
   - pass a credential reference or env expression for the token
   - use the app-provided request and attribution fields inside the event message
7. `Mark RequestId Processed`
   - persist the `requestId` after the FUB call succeeds
8. `Webhook Success Response`
   - return `{ "ok": true, "requestId": "...", "status": "forwarded" }`
9. `Lead Router Error Path`
   - return a `5xx` JSON response for transient failures
   - capture router failures in n8n error reporting

## Follow Up Boss mapping

- Use `source` and `system` = `sylvestri.com`
- Map lead type to event type:
  - `home-valuation`, `seller`, `seller-distress` => `Seller Inquiry`
  - `investor` => `Property Inquiry`
  - everything else => `General Inquiry`
- Person payload should include:
  - `firstName`
  - `lastName`
  - `emails`
  - `phones` when present
- Event message should preserve:
  - `requestId`
  - `leadType`
  - `campaign`
  - `sourcePath`
  - `sourceToken`
  - `propertyAddress`
  - `leadMagnet`
  - all note content

## Environment and credentials

- `LEAD_ROUTER_TOKEN`
- `LEAD_ROUTER_SIGNING_SECRET`
- `FUB_API_TOKEN` or n8n credential reference
- optional persistence backend for dedupe if not using n8n Data Store

## Hardening

- Workflow create/edit is privileged and should stay restricted to operators
- Keep the n8n webhook path unlisted and token-gated
- Do not store plaintext secrets inside workflow JSON
- Keep SMTP notifications in the app layer; the router should not send `bot@sylvestri.com` mail
